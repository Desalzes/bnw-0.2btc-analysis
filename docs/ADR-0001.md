# ADR-0001: Read-only, no-transaction operation (the puzzlebox safety contract)

Status: accepted (2026-05-31)

## Context

puzzlebox works on real-money crypto-prize puzzles with LIVE funded addresses.
An agent with key-derivation + network access could, in principle, construct and
broadcast a transaction that sweeps a prize. That must never happen
autonomously, and solving must be decoupled from claiming.

## Decision

1. **READ-ONLY always** — never construct, sign, or broadcast a transaction;
   never sweep funds. Only read-only blockchain APIs (mempool.space,
   blockstream.info) and offline key derivation.
2. **Candidate-key protocol** — a derived candidate key/seed is recorded at the
   TOP of the puzzle's `STATE.md` under `## !!! CANDIDATE KEY` with the full
   derivation, committed, then STOP. Claiming is the human operator's decision.
3. **Scope** — only the sanctioned puzzles in `puzzles/`. No scanning,
   enumerating, or attacking arbitrary funded addresses.
4. **No large brute-force / keyspace sweeps** without explicit operator
   sign-off (they are low-EV and CPU-pegging — see the btc-02 findings).

## Consequences

- The repo can never autonomously move funds (the catastrophic failure mode is
  structurally excluded).
- Solving is human-gated at the claim step.
- Formalizes, repo-wide, the rails the GSMG and btc-puzzle-monitor routine
  prompts already carried.

## Revisit if

The operator wants a supervised, explicitly-gated claim flow — that would be a
new ADR, not a relaxation of this one.
